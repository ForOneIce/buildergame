# Let game objects explain the actions

Date: 2026-09-12. AI tool: Codex. Grouped project follow-ups.

## Original project instructions

调研下热门游戏的设计语言逻辑，我觉得目前的交互游戏感还是很弱。是不是因为控件本身没有视觉化呈现，比如小镇入口的按钮并没有小镇入口的意象 ，控件上的字太多了，没有仅仅通过按钮的外形能理解功能

比如新建城镇，展开的应该是一张规划图纸，牛皮纸质感，而不是简单的弹窗、选项这些

游览小镇按钮可以显示成地图或者地球，loading是地图展开。

## English translation (AI)

Research the design-language logic of popular games. The current interaction still feels weak as a game. Could this be because the controls do not visually represent their meaning? For example, the town-entry button does not evoke entering a town. The controls have too much text, and their shapes alone do not communicate their function.

For example, creating a town should unfold a planning drawing with a kraft-paper texture, rather than simply showing a popup and options.

The Explore town button can look like a map or globe, with a map-unfolding loading transition.

## Scope and interpretation (AI)

Research recognizable object forms and transitions, then revise the standalone proposal with a physical planning sheet, a folded-map exploration entry and unfolding transition, and the existing door greeting. Short labels and accessible names support object meaning; functional form fields remain available where input is necessary. The folded map is the implementation choice within the user's map-or-globe direction.

The existing preview-only approval gate continues. Games are design references, not sources of copied assets. See [research and object mappings](../docs/game-interaction-language.md) and the [shared interface specification](../specs/0011-shared-game-interface.md). Actual preview QA and final human acceptance remain separate.
